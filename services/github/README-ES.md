# GitHub

Repositorios, issues, pull requests.

## Crear el token

**Settings** → **Developer settings** → **Personal access tokens**.

Los tokens «fine-grained» son preferibles: se pueden limitar a repositorios
elegidos, mientras que un token clásico vale para toda tu cuenta.

Dale **los mínimos ámbitos posibles**. Un agente que lee issues no necesita
escribir código; un agente que abre pull requests no necesita administrar la
organización.

## Conviene saber

El token actúa en tu nombre: lo que escriba el agente aparecerá con tu nombre y
tu avatar. Para distinguir su trabajo del tuyo, crea una cuenta de máquina y
saca el token de ella.
